# Decisions

- Commits are made as repo-local identity `elsiribot` because no git identity was configured.
- `scripts/screenshot.sh` builds the binary before starting sway, so the 15 s window-map timeout excludes compilation.
- `just screenshot` writes to `target/screenshots/<name>.png`, which is already gitignored via `/target/`.
- Screenshot harness waits for sway app_id `fedimix` (what GTK reports under headless sway), not the reverse-DNS application id.
- `Amount::from_sat` uses plain multiplication (no saturation); max supply (2.1e15 sat) fits u64 msat, so overflow cannot occur for valid values.
- `EventStream` derives Clone (async_channel receivers are cloneable, work-sharing) so the UI can hand it to tasks easily.
- tokio is a dev-dependency only (features macros, rt) in core; the async API stays runtime-agnostic.
- DemoBackend keeps event senders in a separate std Mutex (not the state Mutex) because `subscribe()` is sync and must also be reachable from the delayed-notification task; each subscriber gets its own unbounded channel and closed ones are pruned on emit.
- `SendConfirmed` is emitted via `tokio::spawn` + sleep only when a tokio runtime is current; without one it is skipped rather than panicking.
- tokio is now a regular dependency of core (features sync, time) for the demo backend's Mutex and sleep; the Backend trait stays runtime-agnostic.
- Demo refill checks the signing device before the target gap, so NoSaving reports NotSetUp rather than "at target"; `exit_now` also requires a device.
- Task 4: `queue_row` takes the anonymity target as a parameter for the meter; caption fraction is for_spending/target below target, else for_spending/(for_spending+moving); `format::date` computes the local UTC offset via glib and delegates to a pure `date_with_offset` so tests are timezone independent.
- Task 5: core runs on a current-thread tokio runtime parked on its own "fedimix-core" thread (`block_on(pending)`), so no `rt-multi-thread` feature is needed; `CoreBridge::call` returns results through a bounded async-channel consumed by `glib::spawn_future_local`, keeping callbacks `!Send`.
- Task 5: `AppContext::refresh` tags each fetch with a sequence number and drops results older than the newest applied one (stale results never overwrite newer snapshots); fetch errors toast. `on_snapshots` has no unsubscribe: callers capture weak refs and dead views no-op.
- Task 5: initial tab is chosen from the first snapshot (Saving unless no Saving device, then Spending), so the window shows Saving briefly before switching in the no-saving case. Settings/About menu entries toast "not available yet" until their pages exist.
- Task 6: `AppContext::on_snapshots` callbacks return `bool` (false = unsubscribe) so dead views are pruned instead of accumulating. `SavingTab` state (`Inner`) is owned by its root widget via a `connect_destroy` closure and subscribed to weakly, so callers need not keep the handle; `Inner` holds only child widgets to avoid a cycle.
- Task 6: A nested change row is drawn inside its parent's `ListBoxRow` (dim caption, indented) rather than as its own row, so it has no card/separator of its own. The Saving page rebuilds only when `SavingState` differs from the last rendered one.
- Task 6: Added `pango` to the flake's `buildInputs` (hence `LD_LIBRARY_PATH`): ellipsizing labels links libpango directly, and the binary failed to load in the dev shell without it.
- Task 7: `--demo-page saving` forces the Saving tab even without a device (to screenshot the empty state); `apply_start_page` runs once after the first snapshot and picks the tab plus any pushed page. `FedimixWindow::new` now takes the start page and holds `AppContext` in an `Rc` shared by all views.
- Task 7: Pushed pages (Coins, coin detail, Notes) own their `Inner` via `connect_destroy` on the `NavigationPage` and subscribe weakly, so a popped page is pruned on the next snapshot. Coin detail's Freeze switch ignores changes it makes itself while syncing from snapshots and reverts with a toast if `set_coin_frozen` fails.
- Task 7: "Anonymity at exit" on coin detail is derived from the privacy tag (`~N`, `~N (early exit)`, `None (unmixed)`, `None (small change)`) since `Coin` carries no separate field; the Spending bar uses `LevelBar` with the default low/high/full offsets removed so it stays accent-coloured.
- Task 8: The exit-now dialog says "A withdrawal fee applies." because `QueueState` has no fee field; Phase 4 gains the real value. The anonymity target for the level bars comes from `core().settings()` fetched when the page opens (spec default 50 until it returns). The dialog is parented on the nav view (rows are rebuilt on each snapshot), and `exit_now` maps errors through `present::exit_error_message` and always refreshes.
- Task 9: `qr::matrix` returns `Result` (data over QR capacity is an error, not a panic) and the QR is always black modules on a white 4-module quiet zone so it scans in dark theme; `qrcode` is used with default features off. Send validation errors stay quiet until an amount is typed; above-balance is reported inline from `prepare_send`'s `InsufficientFunds`. A Spending `lnbc` invoice hides the amount field. Confirm goes insensitive (with spinner) before `confirm_send` and stays so on success; an in-flight `Cell` guard makes double activation send once. The Receive switcher is a `gtk::Stack` + `StackSwitcher` (titles only; `ViewSwitcher` needs icons). `--demo-page send|receive` open the Spending dialogs, `send-review` drives the Saving review with a demo address.
- Task 10: The Refill dialog reuses `present::confirm_button(Saving, device)` for the confirm label/sensitivity and follows device changes via snapshots while open, because the refill is signed on the Saving device. The outcome toast reads "Refill confirmed" (errors via the core error text) and always refreshes; double confirm is impossible since AlertDialog closes on response.
- Task 11: The window swaps Join and tabs on every snapshot via a dedicated subscriber that stays subscribed (`federation.is_some()`), separate from the one-shot start-page pick; Join hides the tab switchers but keeps the header menu. The Spending Offline banner shows only for `Some(f) if !f.online`. Settings writes are debounced 400 ms after the last edit (one `set_settings` per burst); handlers connect after the initial values are set, so loading never writes. `present::settings_from_form` also range-checks the spin values and rejects an empty server URL; `--demo-page join` pushes the add-federation page.
- Task 12: a refill refused by the core with InvalidAmount (e.g. already at target) toasts the bare reason via `present::refill_error_message`, not the "invalid amount: ..." Display text.
- Task 12: The demo driver lives in the binary (`demo_drive.rs`) and matches controls by visible label (buttons, check buttons, switch rows, activatable rows, tooltips for icon buttons, `Back` pops the deepest pushed page, tab names fall back to the ViewStack pages); header and item menus are opened with `action <app.name>` and by clicking the MenuButton's tooltip. `shot` waits for a line on stdin (10 s cap) unless stdin is a terminal, then a fixed 500 ms; `interact-demo.sh` feeds it from a FIFO so each grim capture happens while the app is paused.
